# LawnLab 5.6 — Cheat Engine trainer and address catalog

Current compatibility and usage: [GOTY + Classic, Snail, Limbo, coin units, Tree height and Endless records](CLASSIC-AND-PROFILE-5.6.md). Both builds have their own CT/catalog; Classic has no native GOTY achievements.


`LawnLab-GOTY-1.2.0.1073.CT` contains all **46 main-window controls**, configurable parameters, Reset all, and address references for both the main trainer and Lawn Studio. `LawnLab-addresses.json` is the accompanying searchable source inventory. Both are generated by `generate_ct.py`; `build.ps1` regenerates them and ships them beside `LawnLab.exe`.

## Start a CT session

1. Open one fresh supported GOTY or Classic game. Use the matching GOTY/Classic CT. Fingerprints are in [the 5.6 compatibility guide](CLASSIC-AND-PROFILE-5.6.md). Select the actual game process in CE: `PlantsVsZombies.exe` for this GOTY installation, `popcapgame1.exe` for this Classic installation. Do not select Classic's launcher.
2. Disconnect or close LawnLab's normal window. The GUI and CT helper cannot own the same game simultaneously. Close other patching trainers too.
3. Open the CT, expand **Session**, and check **Start verified controller**. Select the matching rebuilt **5.6** companion `LawnLab.exe` when prompted. The table rejects older helper versions. Keep its `_internal` directory beside it. The table is not a standalone replacement for that executable.
4. Set any parameter first, then enable the corresponding control. Rows are zero-based 0–5 and must exist on the current lawn; other IDs use the game's numeric plant/projectile IDs. Game pace uses milliseconds per frame: 1, 2, 5, 10, 20 or 50. Lower is faster; 10 is the usual default. Firing delay is 1–255 ticks, with current attack animations allowed to finish.
5. Uncheck a toggle to restore it. One-shot parameter/action entries can be unchecked and checked again to repeat. Destructive actions ask for confirmation. Unchecking a one-shot does not undo it.
6. Use **Reset all** to release controls, or uncheck **Start verified controller** to reset and end the helper. Checking it again starts a fresh helper and asks for the executable again.

Opening the table alone runs no scripts, launches no process and changes no game memory. The address references work without the helper. Control activation explicitly launches a hidden `LawnLab.exe --ct-bridge` process that attaches to the selected game and checks its fingerprint. No driver or injection DLL is installed.

## Why the companion backend is used

The CT sends a small whitelisted vocabulary of toggle/value/action commands to the same `verified_engine.py` implementation used by the GUI. There is no second set of hand-maintained executable patches. All main controls retain shared patch ownership, incompatible-mode handling, instruction checks, rollback, loop gating and bounded hook allocations. The table synchronizes controls disabled by a conflicting mode.

The GUI and helper acquire a per-game named object to prevent simultaneous owners. CE must remain attached to the original selected PID. The helper verifies that its attached PID matches CE's; close duplicate PVZ processes if selection is ambiguous. Do not switch the selected CE process while controls are enabled.

A heartbeat bounds abandoned sessions. Table unloading/process switching attempts cleanup; CE exiting or becoming unresponsive stops the heartbeat and causes the helper to reset after roughly **20 seconds**. Cleanup can still fail if the game has crashed or another tool changed its bytes. A failed rollback or native-call timeout requires restarting PVZ, as described in the stability guide. Do not forcibly terminate an active helper as a normal way to disable controls.

Session files are local: `%LOCALAPPDATA%\LawnLab\ce\<session token>`. A `cleanup-error` file records an unsuccessful final reset; control logs remain in `%LOCALAPPDATA%\LawnLab\logs\controls.jsonl`. No request can evaluate Python/Lua code or select an arbitrary backend method.

## Addresses and offsets included

The table's **ADDRESS REFERENCE** groups contain read-only scripts. Checking one displays its formula/bytes; these entries do not write, freeze, call a native function or enable a patch. They intentionally avoid editable raw pointers that bypass the runtime's stale-entity and conflict checks.

* LawnApp root, Board/profile pointers, sun, coins, frame duration, UI/mode, scene/level, wave counters and next-spawn countdown.
* Plant, zombie and projectile arrays: capacity fields, strides, dead flags, generation IDs, verified health/timing/speed/status fields and equipment-type versus equipment-HP distinctions.
* Seed-bank packets, natural wave composition, projectile damage definitions, potted-plant records, garden supplies and mower structures.
* Every static patch selected by the current controls, temporary mower/preview patches, all six main hook spans, the additional firing-animation guard and their original bytes.
* Native creation/deletion/completion/preview/profile/stage routines, update-loop gate, allocation layouts and runtime parameter locations.

All static locations are **module-relative RVAs**. Heap objects are pointer chains, not persistent absolute addresses. Retained hook caves are per-process allocations and have no fixed address across restarts. The full JSON also inventories every hexadecimal source literal with its file, line and context, along with source SHA-256 hashes. Some literals are instruction bytes, sizes or Windows flags; the inventory explicitly does not label them all as addresses.

Studio's formations, scheduled waves, save backups, profiles and persistent garden/stage workflows remain available in the normal LawnLab interface. Their memory layouts and native locations are in this CT; their full workflows are not duplicated as new CT dialogs. Stop the CT helper before switching to Studio.

## Regeneration and validation

Run `.venv\Scripts\python.exe generate_ct.py`, then `.venv\Scripts\python.exe -m unittest discover -s tests -v`. Tests compare generated artifacts with source, cover every control/patch/hook, reject arbitrary commands and out-of-range values, check heartbeat/response framing, and compile every embedded Lua section with the locally installed CE Lua runtime when available. The installed CE API descriptions in `celua.txt` were consulted; relevant public API references include [createProcess](https://wiki.cheatengine.org/index.php?title=Lua%3AcreateProcess) and [getOpenedProcessID](https://wiki.cheatengine.org/index.php?title=Lua%3AgetOpenedProcessID).

The combined suite has **132 passing tests**, including ten CT-specific checks. Live tests used the installed CE Lua DLL with a CE-API test harness to send 18 adapter/backend commands, including combined economy hooks, a projectile parameter update, conflict synchronization, reset and stop. Packaged-helper checks verify code restoration, exclusive ownership and release after stopping. The interactive CE file picker/table UI has not been exercised by that harness. The gameplay changes shared by the GUI and CT are documented in [GAMEPLAY-FIXES-5.2.md](GAMEPLAY-FIXES-5.2.md).

The CT adapter does not expand the gameplay guarantees in [STABILITY.md](STABILITY.md) or the mode limits in [LAWN-STUDIO.md](LAWN-STUDIO.md). Native reference entries are documentation, not callable Auto Assembler stubs.
